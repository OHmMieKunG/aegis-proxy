# NPMPlus compatibility matrix

Status: authoritative product-gap inventory

Updated: 2026-08-02

Comparison baseline: NPMPlus
[`f6a4db4`](https://github.com/ZoeyVid/NPMplus/commit/f6a4db4da1a78407c423a4e3f3576c380aba88c5)

This matrix compares ordinary supported workflows and outcomes. It does not compare Nginx
directives, database layout, private APIs, source code, or UI pixels. A low-level primitive does
not make a capability complete: **Complete** requires the supported GUI, typed control-plane, and
runtime or operational path needed by an ordinary user.

Classifications:

- **Complete:** the supported end-to-end workflow exists for the stated baseline outcome.
- **Partial:** useful pieces exist, but the ordinary workflow or important behavior is incomplete.
- **Missing:** no supported product workflow exists.
- **Intentionally different:** AegisProxy provides or plans a safer different outcome.
- **Deferred:** a decision or implementation is intentionally postponed.
- **Not applicable:** the pinned NPMPlus baseline does not expose a corresponding ordinary
  workflow, or the behavior is implementation-specific.

The target phase is a planning commitment, not evidence that the capability exists.

## Release interpretation

The matrix may mark a row Complete while the overall product remains pre-release. Production
readiness additionally requires Phase 23 release, recovery, fuzz/soak, supply-chain, protocol, and
independent security evidence. Conversely, an underlying runtime primitive is recorded as Partial
or Missing whenever the supported daily workflow is absent.

# Atomic reload benchmark — 2026-07-16

> Historical benchmark
>
> This document records one Windows development-machine run on 2026-07-16. It is retained for
> traceability, is not a current performance result or production SLO, and must not be generalized
> to the supported Linux deployment. See [`STATUS.md`](../../STATUS.md) and
> [`PLAN.md`](../../PLAN.md) for current evidence and release gates.

## Scope and acceptance budget

This microbenchmark measures `ActivationCoordinator::activate` after a candidate revision is already validated and persisted. It includes candidate snapshot preparation, durable intent/pointer/journal writes, atomic publication, structural probation, commit, and retired background-task shutdown. It excludes file-poll delay, TOML parsing, candidate creation, network traffic, and compilation.

For this minimal route-only fixture on this recorded development machine, the Phase 5 guard budget is p99 at or below 100 ms and maximum at or below 150 ms across 25 serial activations. This is not a production SLO or a capacity claim. Linux local-filesystem results with real directory `fsync`, maximum-size configuration, and concurrent traffic remain required before release.

## Reproduction

```powershell
$env:PATH='C:\Users\mochi\.cargo\bin;C:\TDM-GCC-64\bin;' + $env:PATH
$env:LIBRARY_PATH='C:\tmp\aegisproxy-gccfix;C:\TDM-GCC-64\x86_64-w64-mingw32\lib;C:\TDM-GCC-64\lib\gcc\x86_64-w64-mingw32\10.3.0;' + $env:LIBRARY_PATH
cargo +stable-x86_64-pc-windows-gnu test --release -p aegisproxy-core runtime::tests::benchmark_atomic_reload -- --ignored --exact --nocapture --test-threads=1
```

The ignored test is dependency-free and asserts only final revision correctness. Budget evaluation is recorded here so a slower environment does not create a misleading universal test failure.

The local development guard passed: p99 was 48.101 ms and maximum was 48.228 ms. The separate `managed_file_reload_is_atomic_and_rejects_invalid_change` integration test verifies accepted requests return a complete old or new response and that an in-flight old-snapshot stream finishes after activation. This benchmark does not independently measure request loss.

## Limitations and next evidence

- Add maximum-schema route/upstream/certificate fixtures before defining a production reload SLO.
- Run concurrent sustained traffic and report accepted requests, errors, latency percentiles, CPU, RSS, file descriptors, and network bytes.

# Backup, rollback, and compromise tabletop — 2026-07-19

> Historical security exercise
>
> Results apply to the dated tabletop. See [`STATUS.md`](../../../STATUS.md) for current release gates.

Type: local single-maintainer desk exercise; not an independent review or live recovery drill.

## Scenario

An operator token is stolen after a malicious candidate activates on one HA node. The candidate
routes a host toward a prohibited metadata address. Audit storage then becomes read-only. A recent
encrypted backup exists, but the node and its local state are considered compromised.

## Walk-through result

1. Runtime CIDR validation should reject the metadata endpoint before activation/connect; invalid
   candidate cannot replace active snapshot.
2. If policy bypass or host compromise is suspected anyway, drain/remove node externally and block
   further mutations. Read-only audit storage already makes mutation paths fail closed while data
   plane continues from memory.
3. From a clean authorized host, revoke stolen token, compare fleet revision/hash/node ownership,
   and review authenticated audit chain. Treat all node-readable credentials as exposed.
4. Verify backup authentication/checksums without extraction. Select a known-good config and create
   an authorized forward rollback revision on clean state; never rewrite history/pointers.
5. Rotate admin, audit, age, ACME, DNS, and certificate material reachable from compromised node.
   Rebuild node, validate config/certificates, test isolated routes and SSRF controls, then canary.

## Control evidence reviewed

- candidate CIDR/SSRF, rebinding, failed activation, atomic rollback, audit failure, RBAC/token,
  encrypted-backup tamper, and HA chaos tests;
- admin, backup, HA, and incident runbooks;
- non-root/read-only deployment and optional confinement examples.
